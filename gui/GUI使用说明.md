# RCWA 图形调用入口

在 macOS 中双击同目录的 **启动GUI.command**。程序会自动选择装有 NumPy、SciPy
和 Matplotlib 的 Python，并在本机浏览器中打开界面。保持启动时的终端窗口开启；
关闭该进程会退出GUI并停止尚未完成的计算。

Windows 发布包面向 Windows 10/11 x64 与 Python 3.11/3.12 x64。
先完整解压到可写目录，首次双击 `install_windows.bat` 安装本地环境，
然后双击 `start_gui.bat` 或 `启动GUI.bat`。安装需要联网，后续计算在本机运行。
首次绘图可能需要建立字体缓存。

也可在已有依赖的终端中运行：

```bash
python -m pip install -r requirements.txt
python gui.py
```

界面只监听本机地址127.0.0.1，不需要网络服务或登录。浏览器窗口关闭后，如需
再次使用可回到终端输出的地址；结束终端进程可退出本地服务。

## 基本操作

1. 点击“新建自定义模型”从一层开始，或在“载入示例”中选择已有结构。
2. 输入真空波长、入射角与Fourier截断M。平面周期模式选TE/TM；PML模式可选TE、TM或混合偏振；
   圆锥模式另外输入方位角与s/p或Jones偏振。
3. 查看当前一维结构的x-z截面和选中层的横向介电常数。可切换实部/虚部、
   表面放大、完整膜系或选中层附近。
4. 点击“开始计算”。结果页可自由选择Ex、Ey、Ez、Hx、Hy、Hz，或总电场/总磁场
   强度；可显示模平方、幅值、实部、虚部、绝对相位、去入射载波相位或对数幅值。
   PML模式还可选择对比场，周期模式显示反射/透射效率。计算中可以点击“取消”。

长度均为 **μm**。正入射角沿用求解器的约定，对应负的物理x方向入射波矢。
TE主分量为Ey，TM主分量为Hy。图中的电场分量除以入射电场幅值，磁场分量除以
入射磁场幅值；总E²和H²分别按相应入射强度归一。
一维周期圆锥入射与二维横向周期结构均已支持，操作如下。

## C++ 后端（StableRCWA）

符合条件的一维周期模型（平面、圆锥）由 C++ 一次求解给出各级衍射效率、六个复场分量与相位；圆锥结果还保存完整复 Jones 矩阵。
**二维交叉光栅默认由 Python 求解器计算**（实测 C++ 的二维本征分解在每个 N 上都比 Python 慢，见“速度与磁盘”）；设环境变量 `RCWA_2D_BACKEND=cpp` 才走 C++。
Python 负责建模、读取数据、绘图与保存结果。

| 模型 | 效率、Jones、六复场、相位 |
|---|---|
| 周期平面 TE/TM、周期圆锥入射；材料各向同性且 Fourier 系数取解析积分或 FFT | C++ 一次求解 |
| 二维周期（xz 或 yz 切面）；材料各向同性、解析 Fourier 系数、Li 因式分解、谐波总数 N=(2M+1)(2My+1)≤625 | 默认 Python；设 `RCWA_2D_BACKEND=cpp` 后 C++ 一次求解 |
| 一维的单轴晶体、横向 PML（含混合偏振与自动选参） | Python |
| 二维的横向 PML、单轴晶体、FFT 系数、背景覆盖与磁性介质 | 不支持：界面入口拒绝，不交给任何求解器 |

- 结果页分别显示效率、场图和相位的后端，以及求解、场重建、相位和保存用时。
  正常 C++ 路径不调用 Python 数值求解；`backend.python_solve_seconds=0`、`python_solve_ran=false`，
  未作对照时差值为 `null`。
- 设置 `RCWA_VERIFY_PYTHON=1` 可显式开启效率与传播级 Jones 的 Python 对照。
  对照失败会保留完整有效的 C++ 结果，并记录失败原因；只有实际完成对照才显示差值。
- C++ 不可用、编译失败、超时、求解失败（含二维的 Rayleigh 异常点与数值失败）或二进制结果格式不符时，完整回退 Python 并在 `backend.note` 写明原因；
  遇到 Rayleigh 异常点时 Python 随后给出的中文提示与以前完全相同。
- **怎么打开二维的 C++ 路径**：设环境变量 `RCWA_2D_BACKEND=cpp`，再启动界面。启动脚本不改环境变量，`gui.py` 把自己的环境原样交给工作进程，所以在同一个终端里设好再启动即可：
  macOS 终端 `RCWA_2D_BACKEND=cpp ./启动GUI.command`；Windows 命令行 `set RCWA_2D_BACKEND=cpp` 之后运行 `start_gui.bat`（双击启动时用系统环境变量设置）。
  不设或留空就是默认（Python）；取值不分大小写，只认 `python` 与 `cpp`，别的值（包括还没有实现的 `auto`）按默认处理，并在结果页的说明里写出“无法识别”。
  这个开关只管二维：一维的路由、结果与它无关；`RCWA_BACKEND=python` 仍强制全部 Python，`RCWA_BACKEND=cpp` 不是有效取值，不会打开二维的 C++。
  默认时 `backend.note` 是一句中性的话（“二维周期模型默认由 Python 求解器计算（环境变量 RCWA_2D_BACKEND=cpp 改用 C++）”），结果页以“未用 C++：”开头显示它，不是故障。
  **下面各条写的是打开 `RCWA_2D_BACKEND=cpp` 之后的二维 C++ 路径。**
- 二维走同一个 `rcwa_fields` 程序（协议见 `validation/field_reference_2d/PROTOCOL_2D.md`）：请求带切面方向 `plane`（xz 或 yz）、沿切面的采样数 `nt`（界面的“横向采样数”）与固定坐标 `at`；
  应答的清单与每个 NPY 文件头、字节数、坐标、弱场掩膜都逐项核对，任何一项不符都整体退回 Python。结果文件的键、dtype、形状与 Python 路径一致，旧的显示代码不区分来源。
  二维的 `backend` 段与一维同构；`RCWA_VERIFY_PYTHON=1` 同样才会多做一次 Python 二维求解来核对各级效率。
- 二维应答除格式外还核对**物理自洽**，不符即整体退回 Python 并在 `backend.note` 写明：
  Kx、Ky、kz 按请求独立重算（kz 的取支 Re、Im ≥ 0，传播标志取自解析的 kz，不取自应答自己的 kz）；逐级（每个衍射级对它自己的幅度）的 Rs/Rp/Ts/Tp 与远场 Ez 能否由同一应答的 Ex/Ey 重算（1e-9）；
  各级效率与 Re kz·|E|²/(nI cosθ)（1e-12）；应答头 `ok` 必须是布尔 `true`；
  fields.npy 在叠层之外的**每一行**（z<0 与 z>叠层底面）能否只由远场数组重建（1e-9 加一项随条件数与相位幅角增长的取整允许量）；phase.npy 与 fields.npy 的一致性（1e-9 加幅角允许量）；
  应答里“只报告”的元数据与请求、与调用的墙上时间是否对得上（线程数等于请求、计时不超过墙上时间、本征分解次数在结构层数与总层数之间、没有本征分解时它的残差恰为 0、status 为 ok 时 message 为空）。
  这挡得住“形式正确、数值被改过”的应答（Rs/Rp 对调、共轭、某个分量差 1e-6、H 差一个 Z0、整个相位换成陈旧文件、传播级 kz 取负、读错入射偏振角……）。
  **不论用户的 z 范围是什么**，GUI 总是在叠层之前、之后各多算一行隐藏探针行（z = −h 与叠层底面 + h，h = max(0.02 个波长, 1e-8 µm)；1e-8 µm 的下限让探针离开界面处 1e-9 µm 的“不检查带”），
  入射偏振与相位、反射/透射振幅因此始终与请求钉在一起——也包括用户的叠层之外的行全因取整允许量过大被跳过的极端参数（λ = 1e-9 µm、z ∈ [−1e3, 1e3] µm），例如 psi 被误读成 90° − psi 也能查出；
  校验完立刻从 fields.npz、metrics 和界面看到的所有数据里去掉，所以界面上的 z 轴、形状与没有探针时相同；用户的各行的六个场、E2、弱场掩膜与相位和没有探针时逐位相同，
  **只有一个有界的例外**：用户的行深在强吸收膜里（场比探针行小得多）时，C++ 按“含探针行”的峰值写的弱场掩膜在用户的网格上多掩了一些点，GUI 按用户自己的行重新取峰值并由 Python 补上这些点的相位，
  那些点上两个相位参考（绝对相位、去入射载波）与不加探针的 C++ 运行相差不超过 1e-14 rad，不是逐位相同（实测：macOS 第一个参考逐位相同、第二个 ≤ 2.2e-15；Windows 两个都 ≤ 4.4e-16）；场、E2、掩膜与其余各点的相位仍逐位相同；
  只有程序发布的原始目录 `cpp_fields-编号/` 里的 `fields.npy` 等多出这两行（先 z=−h 那一行，叠层底面 + h 那一行在最后）。
  **看不出的情形**（照实写在这里）：(i) 一套自洽却物理不同的结果，例如求解器内部对调了两层厚度、读错某层折射率、镜像了结构而应答照抄请求，或者把远场与叠层之外的场一致地改写而叠层内部不变（“resynth”一类，只能经由界面与叠层内部发现），
  那只有 `RCWA_VERIFY_PYTHON=1` 的独立求解能发现；
  (ii) 叠层之内（0 ≤ z ≤ 叠层底面）各行的任何改动，以及两个界面（z = 0 与 z = 叠层底面）两侧各 1e-9 µm 内的行：叠层之外的检查看不到，场文件里这些行没有独立的参照（界面两侧的 Ez、Hz 本来不连续，所以那两个窄带也不检查；
  在界面行上把 Ez 变号、H×1.1 因此看不出）；
  (iii) 取整允许量以内的改动：一般小于峰值的 1e-9，掠入射 θ=89.9° 时到约 1e-8（极端幅角更大，实测分布见 PROTOCOL_2D.md 6.3）；波长相对 |z| 极小（例如 λ=1e-9 µm、|z|=1e3 µm）时允许量超过 1e-3 的行与相位检查被明确跳过，并写进 `backend.note`；
  检查的判据相对的是 E 或 H **整族**的峰值，所以较弱的分量只受较弱的保护（PROTOCOL_2D.md 6.3 给出逐分量的检出下限的分布）；
  (iv) 采样点数 nz×nt 加上两行探针会超过协议上限 4000000 时不加探针并在 `backend.note` 写明，那时只有用户自己的叠层之外的行受检查（界面上限 1600×1200 远低于它）；
  (v) `n_dense_solve`、有结构层时的 `max_eig_residual` 只核对为非负的有限数；计时只检查上界（不超过墙上时间的 1.05 倍加 1 s），伪造得比实际小看不出。
  依据、容限的取法与实测残差见 `validation/field_reference_2d/PROTOCOL_2D.md` 第 6 节。
- 界面接受首尾边界之差与周期相差不超过 1e-8·max(周期, 1) µm 的二维模型，而 C++ 只接受 1e-9·周期：偏差超过 5e-10×周期时，请求里把最后一个边界贴齐到“首个边界+周期”，
  这类模型因此仍走 C++。移动量就是那个偏差，不超过 1e-8·max(周期, 1) µm（周期不超过 1 µm 时至多 1e-8 µm）。偏差不超过 5e-10×周期的模型（含精确相符的，这是常态）一个字节也不改；
  偏差在 5e-10 与 1e-9×周期之间的，C++ 本来会接受，也同样被贴齐。C++ 与按原样输入求解的 Python 相差约贴齐量与周期之比（4.9e-9 µm、周期 0.8 µm 时场的最大差为峰值的 1.2e-8），不是逐位相同。
  边界离原点极远而周期极小（例如 1e5 µm 与 1e-6 µm）的模型贴齐也过不了 C++ 的检查，仍整体退回 Python。
- 一次 C++ 调用没有得到被采用的结果时，不留几百 MB 的废目录（一维、二维相同）：
  超时、程序被杀、应答被拒绝、中途异常，以及 **macOS/Linux 上的取消**（SIGTERM）由工作进程自己删掉这一次调用建的 `cpp_fields-编号/` 与 `cpp_fields-编号.tmp-*`；
  **Windows 上的取消**是 `TerminateProcess`，工作进程没有机会清理（以前会留下 1600×1200 时的 391 MB），所以界面服务器在工作进程结束之后，把**这个任务自己的结果目录**里所有
  `cpp_fields-<32 位十六进制编号>` 与 `cpp_fields-<编号>.tmp-*` 删掉（别的文件、别的目录一概不碰；符号链接和目录联接只删链接本身；文件暂时被占用就重试，正常的取消 0.1–0.2 s，文件被别的进程长期占住时最多约 6 s）。
  应答被采用之后、还在保存六分量数据时被取消的任务，两个平台都会把被采用的目录删掉（任务已取消，结果不用了）。
  没有清理的情形：被采用的调用保留 `cpp_fields-编号/`（见“结果文件”），被采用之后工作进程才失败时也保留；结果已经完整写完（`metrics.json` 与 `fields.npz` 都在）的任务不清理；已经结束的任务取消不起作用。

### 速度与磁盘（实测，一个时间点的快照）

二维 C++ 路径**比 Python 慢**，这是二维默认走 Python 的原因（`cpp_backend.DEFAULT_BACKEND_2D`；改回 C++ 的条件：C++ 的本征分解并行化，并在界面默认线程数下实测不慢于 Python）。
这一节的数字都是在 `eig_qr` 多线程化之前测的；现在 `eig_qr` 在矩阵阶数 2N ≥ 192 时使用多个线程，二维默认路由仍是 Python。
界面默认线程数（Mac 上 8 个）下：N = 169 / 289 / 625 时 C++ 0.93 / 1.81 / 13.5 s，Python 0.69 / 1.72 / 9.24 s（预设那样一个结构层加两层均匀膜，nx=360、nz=220，两次取较小值，平均负载约 8）。
下面是单线程的数字（`gui_worker.compute`，二维预设的“一个柱层 + 两层均匀膜”，M=My=4…12，横向采样 nx=360、纵向 nz=220，
各 3 次交错运行取最小值；C++ 一个线程，Python 一个 BLAS 线程；时间包含建模、求解、校验与保存，不含程序启动前的编译）：

| N | C++ | Python（Apple M1 Pro、macOS 15.4，`/usr/bin/python3`，NumPy 2.0.2 / Accelerate） | C++ ÷ Python |
|---|---|---|---|
| 81 | 0.70 s | 0.37 s | 1.9 |
| 169 | 1.00 s | 0.65 s | 1.5 |
| 289 | 2.06 s | 1.70 s | 1.2 |
| 441 | 6.15 s | 4.94 s | 1.2 |
| 625 | 17.4 s | 10.5 s | 1.7 |

测量时 macOS 的平均负载 10–18（别的任务同时在跑），所以绝对值只是参考；C++ 在每个 N 上都比 Python 慢。
同一个测量在 Windows（Ryzen 5950X，Python 3.11 / NumPy 1.26 / OpenBLAS 单线程，MinGW g++ 13.1 编出的程序；测量时机器另有约 50% 的 CPU 被别的任务占用，没有取到平均负载）：
C++ 0.75 / 1.20 / 2.97 / 8.44 / 22.8 s，Python 0.36 / 0.64 / 1.83 / 4.78 / 12.2 s（N = 81 / 169 / 289 / 441 / 625），C++ 在每个 N 上都慢 1.6–2.1 倍。
测这些数字时，C++ 求解器只按**结构层**并行，所以只有一个结构层的模型无论开多少线程都只用约 1 个核；`eig_qr` 多线程化之后，盈亏平衡点已经移动，上面的数字没有重测。要强制某一边，用 `RCWA_BACKEND=python`（Python）或 `RCWA_FIELDS_EXE`（指定程序）。
磁盘：采样 1600×1200 时 `cpp_fields-编号/` 里保留的原始 NPY 是 6·1200·1600·16 B（fields）+ 2·6·1200·1600·8 B（phase）+ 2·6·1200·1600 B（mask）≈ 391 MB（按形状算出，隐藏探针行再多 0.17%），
`fields.npz` 另存 `phase_values`、`phase_masks`。不需要原始 NPY 时可以在计算完成后删掉该目录，界面显示与导出只读 `fields.npz`。
校验的额外开销（N=625、nt=1600、nz=1200）见 `validation/field_reference_2d/PROTOCOL_2D.md` 6.4。
- 圆锥 Schur 场采用完整传播矩阵；平面有限层精确零根保留线性场项。
  诊断记录实际后端的 `n_schur` / `cpp_zero_modes`；显式核对时另记录 Python 计数。
- 六分量的绝对相位和去入射载波相位均由 C++ 预存，切换相位显示直接读取。
  每个分量的幅值低于或等于该分量峰值的 10⁻⁶ 时掩膜，零分量的相位没有定义；界面显示包裹相位，不展开。
  去载波不去掉方向符号或 Jones 的整体相位。历史 NPZ 继续沿用原 Python 显示规则。
- 点击“取消”会终止工作进程及正在运行的 C++ 程序、编译器；Windows 使用作业对象。取消后该任务目录里 C++ 留下的 `cpp_fields-*` 也被删掉（见上面的清理说明）。

**程序的位置与构建。** GUI 使用 `bin/rcwa_fields`（Windows 为 `bin\rcwa_fields.exe`）。
`cpp_fields_backend.py` 复用编译与进程管理工具，从 `../examples/rcwa_fields.cpp` 与 `../include` 构建；
界面启动时预编译，源码更新后自动重编。编译日志为 `bin/rcwa_fields.build.log`。
系统依次查找 `c++`、`g++`、`clang++`，Windows 再查找 `cl`。也可手工编译：

```bash
mkdir -p bin
c++ -std=c++17 -O2 -I ../include -I ../examples ../examples/rcwa_fields.cpp -o bin/rcwa_fields
```

Linux 另加 `-pthread`；MinGW 另加 `-static`，输出名为 `rcwa_fields.exe`；
MSVC 用 `/std:c++17 /O2 /EHsc /utf-8` 并配置 include 路径。
Windows 双击启动时可设置 `RCWA_CXX` 为编译器完整路径，或从 MSVC 的 x64 Native Tools 命令行启动。
完整场协议已在 macOS 与 Windows（Ryzen 5950X、Python 3.11、MinGW g++ 13.1，C++ 程序由界面的自动编译器编出）验证；在 Windows 上的结果见“本版验证”一节。

| 环境变量 | 作用 |
|---|---|
| `RCWA_BACKEND=python` | 强制全部使用 Python（一维、二维都是；取别的值，包括 `cpp`，不起作用） |
| `RCWA_2D_BACKEND=cpp` | 打开二维周期模型的 C++ 路径；不设（或 `python`）时二维走 Python；只管二维，别的值按默认处理并在说明里写出 |
| `RCWA_FIELDS_EXE=路径` | 覆写完整场协议程序，优先于旧覆写 |
| `RCWA_JSON_EXE=路径` | 仍供 `cpp_backend` 旧效率 API 使用；GUI 只设置它时完整回退 Python 并说明原因 |
| `RCWA_VERIFY_PYTHON=1` | 显式增加一次 Python 求解作效率与 Jones 对照 |
| `RCWA_CXX=编译器` | 指定编译器名字或完整路径 |
| `RCWA_CPP_TIMEOUT=秒` | 单次 C++ 调用时限，默认 1800；超时终止并回退 Python |

完整场请求的 `solve` 是单点旧 JSON 求解请求，另有 `sampling`、本次新建的 `output_dir` 与 `request_id`。
标准输出只返回效率、诊断和文件描述；六复场和两套相位/掩膜通过 NPY 二进制传输。
输出先写入临时目录，全部完成后发布到本次结果子目录；已有输出目录会拒绝覆盖。
读取前核对版本、请求标记、dtype、字节序、shape、C 布局、文件长度、有限值与掩膜。
旧 `rcwa_json` 程序与协议保留，供效率专用调用与回归验证。

## PML 混合偏振

横向PML模式的偏振可选 **混合偏振 · Jones（TE+TM 叠加）**，再设置ψ、δ，含义与圆锥模式相同：
`[Es, Ep] = [sin(ψ) exp(iδ), cos(ψ)]`，s=TE（E沿y），p=TM（H沿y）。

- 结构沿y不变、材料各向同性、入射面为x-z面时，TE与TM严格解耦（x向拉伸的PML只引入对角张量），
  因此程序在同一离散下各求解一次后按Jones权重叠加。这是离散解的严格叠加，不是近似；
  截断误差是TE、TM各自误差的加权组合，M与PML须同时满足两种偏振。计算时间约为两倍。
- 权重为 `w_TE = σ·Es`、`w_TM = σ·nI·Ep`（TM原始结果以Hy=1计，|E_inc|=1/nI）；
  θ<0时σ=−1，与圆锥模式s/p基随面内波矢翻转的约定一致，p̂×ŝ=k̂ 对任意θ成立。
- δ=+90°为正螺旋度（Im(E*×E)沿k̂），δ=−90°为负螺旋度。
- |E|²与面内能流Sx、Sz没有TE/TM交叉项，等于两偏振按|Es|²、|Ep|²加权；六个分量均非零，
  可分别查看幅值与相位。Sy来自交叉项，是圆/椭圆偏振真实存在的横向能流。
- 开启自动选参时，TE、TM交替各自选参，每次从另一偏振选定的参数开始，直到两者在同一组
  窗口、PML和M下都满足判据；结果页分别列出两种偏振的记录。
- 平面周期模式不提供此选项；周期结构的任意偏振请用圆锥模式并令φ=0。

正确性核对（作者早先的 Python 包里的 `validation/test_pml_jones.py`，未收入本仓库）：周期极限下与独立的圆锥矢量求解器φ=0六分量复场
一致到10⁻¹³量级；均匀介质中带有效PML的场与解析平面波（|E|=1、横波、H=n k̂×E、Jones还原、
螺旋度）一致到10⁻¹⁵量级；孤立圆柱与解析Mie叠加的电场相对误差约0.3%，与单独TE/TM同量级。

## 单轴晶体（各向异性）

“周期 RCWA · 平面入射”（TE/TM）中，层的折射率可写成 `no/ne@轴`，表示光轴沿 x、y 或 z 的
单轴晶体，例如 `1.658/1.486@x`；分段光栅的折射率列表也可以这样写，并可与普通折射率混写。
no、ne 均可带虚部表示吸收。

- TE（Ey）只感受 εyy；TM 的 Ex 感受 εxx、Ez 感受 εzz。例如光轴沿 x 时，垂直入射的 TM
  感受 ne，TE 感受 no。
- 结构预览按偏振显示主场感受的分量（TE：εyy，TM：εxx），层表和悬停标签显示完整写法。
- 入射区、出射区、PML 背景须为各向同性；圆锥、二维与 PML 模式暂不支持单轴材料，会明确提示。
- 方程与验证写在作者早先的 Python 包的报告《各向异性第一档实现与验证》里，尚未收入本仓库。

## 圆锥入射

在“求解方式”选择 **周期 RCWA · 圆锥入射**，输入方位角φ（单位为度）。
选择s、p或“自定义 Jones 偏振”；自定义时设置混合角ψ与s相对p的相位δ：

`[Es, Ep] = [sin(ψ) exp(iδ), cos(ψ)]`。

- ψ=90°为s；ψ=0°为p；ψ=45°、δ=0°为等幅同相线偏振。
- ψ=45°、δ=±90°为两种圆偏振；符号按程序时间因子exp(−iωt)定义。
- θ相对表面法线。程序物理入射方向为
  `k/k0 = nI (−sinθ cosφ, −sinθ sinφ, cosθ)`。
  s单位矢量由`atan2(ky,kx0)`给出，p=s×k̂；θ<0时不要直接套用θ>0的偏振符号。
- 结构仍沿y不变，图中显示y=0的x-z截面；非零ky使s/p耦合，六分量均由求解器计算。
- 结果表显示各级总效率，以及该级出射面中的s/p效率。NPZ另保存复Jones矩阵
  `Jr/Jt`（形状[级次, 出射s/p, 入射s/p]）、`orders`、`flux_r/flux_t`和`jones_in`。
- 当前圆锥模式限于周期结构，不能与横向PML同时使用。

“载入示例”中的 **Meent 已核对算例 · 圆锥** 可直接计算。它使用解析材料系数；
默认M=200沿用原教程，并非所有局部场量均已充分收敛。详细对照、FFT采样影响和
M=400的结果写在作者早先的 Python 包的《圆锥衍射核对报告》里，尚未收入本仓库。
原教程`phi=30`为弧度；本例已转换到度并处理两套程序的偏振/场约定。

从Python直接打开：

```python
launch_gui(stack, name="圆锥模型", lam0=1.053, theta_deg=66.36,
           phi_deg=5., pol="jones", psi_deg=45., delta_deg=90., M=100)
```

`phi_deg`显式给出（包括0）即进入圆锥模式；`pol="s"`或`"p"`选择纯偏振。

## 二维刻线的俯视与联动剖面

1. 在“载入示例”选择 **二维刻线与膜系 · 双视图**，或将“求解方式”改为“二维周期 RCWA”。
2. 设置x/y周期、x截断M和y截断My；当前二维入口限制`(2M+1)(2My+1)≤625`，每方向0～30。
   截断为0用于特殊退化检查；一般二维图案需要两个方向均保留足够谐波。
3. 点击层列表选择层：左图显示该层真实材料的xy俯视图，右图显示贯穿全部层的剖面。
4. 选择xz（固定y）或yz（固定x），拖动滑块或输入剖切坐标。联动在浏览器内完成，
   **不进行RCWA求解，也不往返请求服务器**。Re/Im ε切换同时作用于两幅图。
5. “二维分段介质”层按y区间分组，各区间独立填写x边界与折射率。
   修改y边界后点“更新 y 分段”；新区间按中点继承原区间的x剖面，随后可继续编辑。
   点击“应用到结构”提交并更新材料图，支持移位的周期起点。
6. 点击“开始计算”，本次六分量场图采用当前剖面方向与位置；结果标明固定坐标。
   结构页再次移动剖切线只更新几何预览，原场图仍对应已保存计算。改变场切面需重新计算。

二维界面使用Li因式分解的解析材料系数，默认由 `2drcwa/rcwa2d.py` 求解（`backend.fields` 为 `python`）。设环境变量 `RCWA_2D_BACKEND=cpp` 后，符合条件时（各向同性、解析Fourier系数、`(2M+1)(2My+1)≤625`）
由 C++ 一次求解各级效率、切面六复场与相位（`backend.fields` 为 `cpp`）；C++ 不可用或任何一步失败时完整回退 `2drcwa/rcwa2d.py`，结果文件格式不变。
**二维材料FFT、二维横向PML、二维单轴晶体与磁性介质尚未接入**：界面明确提示并拒绝这些配置，它们在二维里是“不支持”，没有任何求解器会去算
（C++ 失败时的回退只针对已接受的各向同性、解析 Fourier 模型）；原一维、圆锥模式的解析/FFT选择保留。

已有二维Python模型可直接调用：

```python
# stack2d 是原二维求解器的 Stack2D
launch_gui(stack2d, name="我的二维结构", lam0=1., theta_deg=20.,
           phi_deg=30., M=4, My=4, pol="jones", psi_deg=45., delta_deg=90.)
```

二维入射Jones基沿用该内核的φ定义：
`s=(-sinφ,cosφ,0)`，`p=(cosθ cosφ,cosθ sinφ,sinθ)`。
θ为负时，与一维圆锥模块按横向波矢atan2定义的基可能存在整体符号变化；
跨模块比较混合偏振应按物理矢量核对，不能直接照搬Jones符号。

二维NPZ场分量形状为`(nz,npts)`；`t`是沿剖面的变化坐标，`x/y`是对应各横向
采样点的实际物理坐标（固定方向是一列常数），`z`为纵向坐标。
另存`slice_plane/slice_at`和二维`orders`（每行为m,n），以及Rs/Rp/Ts/Tp。
当前二维输出是所选切面，不是完整三维场体积。

## 自动选择PML参数

“自动PML · 孤立介质条”示例已经开启自动选参。其他一维PML模型可在PML设置下
勾选 **自动选择 PML 参数**。手动模式继续使用输入的固定参数。

- **边界对比场残余目标**：默认0.1%，是PML最外侧对比场主分量的RMS相对物理区
  对比场RMS的比例。它是吸收诊断，不能解释成反射率或真实场误差。
- **另做物理区验证**：默认开启；分别提高M、加厚PML检查同一物理区域的场。
- **物理区验证场量**：默认主复场（TE为Ey、TM为Hy），也可选电场矢量。
  默认容许变化1%。电场矢量对介质界面和尖角更敏感，可能需要更大的M。
- **高级限制**：默认最多8次求解、M≤300、两侧厚度各不超过初值4倍、时间预算300秒。
  时间在两次求解之间检查，不能中断已进入的单次数值计算；“取消”按钮可终止整个工作进程。

自动过程只外扩PML及相应的平面背景，不移动、缩放或重复真实刻线；原物理区两端和
背景缓冲距离保持不变。强度和渐变次数沿用输入。计算窗扩大时增加M，并按比例增加
显式FFT采样点，保持谱带宽和材料采样间距；这并不自动保证所有局部场量的离散精度。

结果页区分三类状态：

1. **边界残余达标／未做物理验证**：关闭独立验证时的结果。
2. **主复场／电场矢量稳定性验证通过**：所选场量通过独立精化检查。
3. **达到上限／未完成验证**：预算或参数上限不足，仍保留最后算出的结果与具体原因。

绿色“通过”只针对指定场量和监测网格的稳定性，不表示完整六分量、峰值或几何切片
已经达到严格误差保证。验证用的试算不会强制成为最终采用结果；迭代表突出标出实际
采用的一次，界面输入框与下载的本次模型同步为真实采用的M、窗口和PML参数。

每次自动运行另外保存：`requested_model.json`（原始请求）、`adaptive_pml.json`
（完整试算与判据记录）。`model.json`保存实际采用模型；原始请求可独立下载。

高级Python/JSON输入还支持 `roi=(xmin,xmax,zmin,zmax)`、`width_growth`、
`spectral_growth`和监测点数。默认ROI是初始两侧PML之间的物理区，z覆盖全部层并在
上下各延伸0.25λ；加入层中心采样。结构几何离散、ROI采样和热点峰值仍需按需求验证。

当前自动扩窗接口支持非磁性一维TE/TM及其混合偏振、平面分层背景。它不扩展圆锥或二维PML能力。
完整方法与实测写在作者早先的 Python 包的《自适应PML实现与验证》里，尚未收入本仓库。

## 计算与显示耗时

结果页分别显示电磁求解、场重建、数据处理、保存和工作进程加载耗时；选择场分量后
还显示本次出图时间或“已缓存图像”。

- 每次计算只进行一次电磁求解。六个场分量由同一组模式和振幅重建。
- 一维TM与圆锥场重建现在按层批量处理，同一层的介电矩阵不再对每个z重复分解。
- 求解进程只生成数值数据；常驻GUI服务按需绘制当前图像，不提前画所有相位/对比场。
- GUI启动时提前加载绘图库。复场缓存最多3个结果且总量不超过128 MiB；再次显示同一图
  直接使用已有PNG。旧记录继续可用，原始数值数据不会被覆盖。
- GUI为每次计算启动独立进程，便于取消和释放内存，因此仍有一次环境加载成本。
- 求解进程的 BLAS/LAPACK 线程数默认取物理核数（Apple 芯片取性能核数，最多16），
  启动终端和结果页都会显示。同一时间只运行一个计算，可放心占满CPU；需要固定时，
  启动前设置环境变量 `RCWA_THREADS=4`（任意正整数）。
- macOS 启动脚本优先使用系统自带的 `/usr/bin/python3`：在 Apple 芯片上它是原生
  arm64，NumPy 2 调用 Accelerate。x86 Anaconda 在 Apple 芯片上经 Rosetta 转译，
  同一算例实测慢约5倍。需要其他解释器时设置 `RCWA_PYTHON`。

## 六分量与已有结果

在“计算结果”页的“显示分量”“显示量”“场类型”“配色”中切换。
配色新增 **Turbo · 多彩**，也可选Inferno、Viridis、Plasma；“自动·原配色”保留

保存当前图像会下载所选配色的PNG；不同配色独立缓存。
切换只读取已经保存的复场数据，不重新运行RCWA。可通过“已保存的计算结果”

平面一维TE下Ex、Ez、Hy恒为零；平面一维TM下Ey、Hx、Hz恒为零。这些分量仍可选择，

其余分量的低幅值节点也会屏蔽相位。去入射载波相位仅消除空间载波，保留矢量
分量的正负方向相位，例如均匀介质TE入射场的Hx可能仍显示π。

不被改写；“下载六分量数据”生成独立的 `fields_six.npz`。

NPZ中的复场仍采用求解器的原始归一约定（平面TE为Ey入射幅值1，TM为Hy入射幅值1；圆锥/二维为总入射E幅值1，原始H为Z₀H）。
六分量导出另给出 `E_incident_amplitude`、`H_incident_amplitude`，用来转换为
与图中一致的归一化。选择总E²/H²时不提供矢量“总相位”，须先选定单个分量。

## 查看和编辑介电结构

选中一个**分段层**后，可在“傅里叶系数计算”中选择：

- **解析积分 · 分段精确**：对当前分段常数材料精确积分，保留原有默认方式。
- **FFT · 均匀采样**：在整个计算周期内作均匀中点采样，实际调用FFT计算材料系数。

一维各向同性周期平面/圆锥模型的 FFT 也走 C++ 后端，使用随头文件内置的 BSD-3-Clause pocketfft，无需额外安装。
采样原点、归一化及 ε、1/ε 的独立展开与 Python 分支一致；PML 和单轴晶体仍由 Python 计算。

FFT采样点数N可以手动输入，填0时自动选择。必须满足 `N≥4M+1`，界面会显示
实际点数和采样间距。用“应用至所有分段层”可批量切换多层模型。均匀层继续使用
其解析模式。模型文件和计算结果都会记录各层实际使用的方法和FFT点数。

这个选项改变的是 **ε及1/ε的Fourier系数计算方式**，两条分支使用同一RCWA
本征求解和S矩阵；这里的“解析积分”不表示整个电磁问题存在解析解。
对于分段边界，FFT引入额外的采样误差，应增加N核对收敛。
实算对比写在作者早先的 Python 包的《FFT分支核对报告》里，尚未收入本仓库。

点击截面中的层或层列表中的一行，可编辑该层名称、厚度及材料。
均匀层输入一个折射率；分段层输入边界坐标和各段折射率。边界数必须比材料数
多1，首尾之差必须等于横向计算宽度。复折射率可写为 `1.5+0.02j`。

截面与横向剖面显示的是输入材料的精确分段分布，按 **εᵣ=n²** 计算。
它们没有经过有限Fourier级数平滑，因此可以直接检查当前几何是否正确。
PML使用斜线区域独立标出，其数值吸收不作为真实材料介电常数的虚部显示。

层列表支持添加、复制、上移、下移和删除。更改层参数后点击“应用到结构”，
更改计算宽度或外部介质后点击“更新预览”。改变计算宽度时，分段坐标也应相应
调整；GUI不会静默缩放光栅尺寸。

PML模式下每个分段层都需要背景折射率；均匀层可留空自动推断。实际结构在两侧
PML内必须等于平面背景，否则会提示具体出错的层。详细适用边界写在作者早先的 Python 包的
PML 说明里，尚未收入本仓库。

## 从现有 Python 结构直接打开

若已有 `rcwa1d.Stack`，无需重新输入各层：

```python
from gui import launch_gui

# stack 是现有的 rcwa1d.Stack
launch_gui(stack, name="我的光栅", lam0=1.053,
           theta_deg=66.36, M=100, pol="TE")
```

PML模型同时传入背景和PML：

```python
from gui import launch_gui
from pml import LateralPML

launch_gui(stack, name="有限光栅", lam0=1.053, theta_deg=66.36,
           M=120, pol="TE", pml=LateralPML(1.5, 1.5),
           background=[1.0] + [None] * (len(stack.layers) - 1))
```

本入口当前显示非磁性结构，磁导率要求为1。支持原求解器中的均匀层与分段常数层。

## 保存和载入模型

“保存模型”将当前参数导出为JSON；“载入模型”可恢复该文件。随包的
`examples/models/` 已提供各预设对应的模型文件。也可先从Python导出：

```python
import json
from pathlib import Path
from gui_models import from_stack

model = from_stack(stack, lam0=1.053, theta_deg=66.36, M=100)
Path("my_model.json").write_text(json.dumps(model, ensure_ascii=False, indent=2), encoding="utf-8")
```

随后运行 `python gui.py --model my_model.json`。

## 结果文件与计算范围

每次计算独立保存到 `results/gui_runs/日期时间-编号/`，含：

- `model.json`：本次实际使用的参数快照；
- `metrics.json`：数值摘要，周期模型包含各级效率；`backend` 段记录效率、场图、相位各由谁计算、
  求解与读取用时，以及显式验证时两个求解器的差值，圆锥入射另有 `min_abs_lambda` 与 `degenerate_mode_warning`（见“C++ 后端”一节）；
- `cpp_request.json`、`cpp_response.json`：调用C++程序时的请求与应答（仅在调用了C++时生成）；
- `cpp_fields-编号/`：完整 C++ 调用的六场、两套相位/掩膜和坐标 NPY 文件（只有被采用的调用才保留；超时、取消、被拒绝的调用会删掉自己建的目录）；
- `fields.npz`：坐标、六个复场分量、E²/H²、相位及ε数组；完整 C++ 结果另有版本、后端、六分量两套相位与掩膜；
- `fields_six.npz`：按需生成的六分量导出，也支持旧记录；
- 按需生成的 `view_v6_*.png` 与相应显示元数据；旧版 `field.png/phase.png/contrast.png` 下载地址仍可用；
- `worker.log`：计算日志。

按需显示的分量图保存在该次结果目录的 `view_v6_*.png` 中。
程序压缩包不打包个人运行目录；升级前可将原有 `results/gui_runs` 复制到新版同名位置。

修改输入后，旧结果会标注“参数已修改”，避免将上一组参数的图误认为新结果。
PML灰色侧区不计入物理场强峰值；峰值仍是当前采样网格上的值，需对M、场图采样
和PML参数做收敛检查。

一维/圆锥入口允许M为1–600；二维每方向0–30且总谐波数≤625。最多256层，横向/z绘图采样最多1600/1200点。
更大的任务可通过原Python接口执行。模型预览不进行电磁求解。
